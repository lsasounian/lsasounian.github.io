Resiliência

Cinco camadas que protegem o sistema quando o ambiente falha — cada uma com responsabilidade distinta, todas integradas para não se sobrepor.

Circuit Breaker Bulkhead Retry + Backoff Cascading Timeout Backpressure anyio Redis
Contexto

Por que resiliência em multi-agent é diferente

Em um sistema single-agent, uma falha afeta uma requisição. Em multi-agent, uma falha de um componente downstream se propaga pela cadeia: o agente de busca trava, o agente de booking espera, os slots do bulkhead se esgotam, o Redis acumula, e um problema de um serviço derruba o sistema inteiro.

O padrão clássico de "adicionar um retry" não resolve — muitas vezes piora. Um retry imediato em cascata multiplica a carga no exato momento em que o serviço já está sobrecarregado. A solução é compor cinco mecanismos com responsabilidades distintas:

Sem resiliência: API de hotéis leva 2s para responder com erro └─► 3 retries imediatos × 2s = 6s de espera por request └─► 100 requests simultâneos × 6s = sistema travado └─► Slots do bulkhead esgotados └─► Redis acumula indefinidamente └─► API de hotéis fica ainda mais sobrecarregada Com as cinco camadas: API de hotéis começa a falhar └─► Circuit Breaker detecta 5 falhas → abre → falha imediata └─► Retry não é tentado (CircuitOpenError propagado) └─► Bulkhead libera slots imediatamente └─► Cascading budget evita espera nas camadas acima └─► API de hotéis tem chance de se recuperar sem pressão

Fluxo

Ordem de aplicação

A ordem importa. Circuit Breaker antes do Bulkhead significa que chamadas para serviços degradados não consomem slots. Bulkhead antes do Retry significa que o isolamento existe independente de quantas retentativas acontecem.

Request chega ao endpoint │ ▼ 1. Circuit Breaker ──OPEN──► CircuitOpenError (imediato, sem retry, sem slot) │ CLOSED ou HALF_OPEN ▼ 2. Bulkhead ─────FULL──► BulkheadFullError (sem esperar, sem tentar) │ slot disponível ▼ 3. Cascading Timeout Budget (X-Timeout-Budget: 22.4) │ budget > 0 ▼ 4. with_retry() ├── falha retentável → backoff + jitter → retenta │ └─► cada falha alimenta o Circuit Breaker automaticamente ├── non_retryable → propaga imediato (sem gastar tentativas) └── CircuitOpenError → propaga imediato (circuit abriu durante retry) │ sucesso ▼ 5. @idempotent_node (garante que retry no nó não duplica efeito externo)
Por que essa ordem específica

Circuit Breaker primeiro evita que chamadas destinadas a falhar consumam recursos de Bulkhead. Bulkhead segundo garante isolamento mesmo que o CB não tenha aberto ainda. Retry por último porque só faz sentido retentar dentro de um slot já adquirido — não faz sentido adquirir um novo slot para cada tentativa.

Camada 1

Circuit Breaker

O Circuit Breaker monitora falhas consecutivas por serviço downstream. Quando o threshold é atingido, ele "abre" o circuito e rejeita todas as chamadas subsequentes imediatamente — sem tentar, sem esperar timeout. Depois de um período de recuperação, transita para HALF_OPEN e permite uma chamada de teste.

falhas >= failure_threshold CLOSED ──────────────────────────────────► OPEN (normal) (falha imediata) ▲ │ │ │ recovery_timeout segundos │ success_count >= success_threshold │ │◄────────────────────────────────────────┤ HALF_OPEN │ (1 chamada de teste)◄────────────────────────┘
Por que três estados e não dois

CLOSED → OPEN é simples: detecta falha, para de tentar. O estado HALF_OPEN é o que diferencia um circuit breaker útil de um inútil. Sem ele, o sistema ficaria em OPEN para sempre ou voltaria a CLOSED sem garantia de que o serviço recuperou — e abriria de novo imediatamente. HALF_OPEN permite testar com uma única chamada antes de assumir que o serviço está saudável, sem abrir para tráfego completo.

Implementação completa

Decisão de design: asyncio.Lock no check de estado

A transição de estado (CLOSED → OPEN → HALF_OPEN) é protegida por asyncio.Lock, mas a execução da função em si ocorre fora do lock. Isso evita que o lock bloqueie corrotinas enquanto aguardam I/O — apenas a decisão de estado é serializada, não a execução.

python circuit_breaker.py 
# circuit_breaker.py
# Um CircuitBreaker por serviço downstream.
# Criado uma vez, compartilhado entre todos os requests via CircuitBreakerRegistry.

import asyncio
import logging
import time
from dataclasses import dataclass
from enum import Enum
from typing import Callable, Any, Type

logger = logging.getLogger(__name__)


class CircuitState(Enum):
    CLOSED    = "closed"
    OPEN      = "open"
    HALF_OPEN = "half_open"


@dataclass
class CircuitBreakerConfig:
    failure_threshold: int           = 5
    success_threshold: int           = 2    # sucessos para fechar do HALF_OPEN
    recovery_timeout: float          = 30.0 # segundos em OPEN antes de tentar HALF_OPEN
    expected_exception: type        = Exception


class CircuitOpenError(Exception):
    """Levantada quando o circuit breaker está OPEN.
    Não deve ser retentada — o circuit já detectou que o serviço está degradado."""


class CircuitBreaker:
    def __init__(self, name: str, cfg: CircuitBreakerConfig | None = None):
        self.name              = name
        self.cfg               = cfg or CircuitBreakerConfig()
        self._state            = CircuitState.CLOSED
        self._failure_count    = 0
        self._success_count    = 0
        self._last_failure_time: float | None = None
        self._lock             = asyncio.Lock()

        # Contadores cumulativos para métricas / CloudWatch
        self._total_calls         = 0
        self._total_failures      = 0
        self._total_short_circuits = 0

    async def call(self, fn: Callable, *args, **kwargs) -> Any:
        # Verifica e (eventualmente) transita o estado dentro do lock.
        # A execução ocorre FORA do lock para não bloquear outras corrotinas.
        async with self._lock:
            if self._state == CircuitState.OPEN:
                if self._should_attempt_reset():
                    self._transition_to(CircuitState.HALF_OPEN)
                else:
                    self._total_short_circuits += 1
                    raise CircuitOpenError(
                        f"[{self.name}] Circuit OPEN. Próxima tentativa em "
                        f"{self._seconds_until_retry():.1f}s."
                    )

        self._total_calls += 1
        try:
            result = await fn(*args, **kwargs)
            await self._on_success()
            return result
        except self.cfg.expected_exception as exc:
            await self._on_failure(exc)
            raise

    async def _on_success(self) -> None:
        async with self._lock:
            if self._state == CircuitState.HALF_OPEN:
                self._success_count += 1
                if self._success_count >= self.cfg.success_threshold:
                    self._transition_to(CircuitState.CLOSED)
            elif self._state == CircuitState.CLOSED:
                # Reseta contador a cada sucesso — falhas precisam ser consecutivas
                self._failure_count = 0

    async def _on_failure(self, exc: Exception) -> None:
        async with self._lock:
            self._total_failures   += 1
            self._failure_count    += 1
            self._last_failure_time = time.monotonic()

            if self._state == CircuitState.HALF_OPEN:
                # Falhou no teste — volta para OPEN imediatamente
                self._transition_to(CircuitState.OPEN)
            elif self._state == CircuitState.CLOSED:
                if self._failure_count >= self.cfg.failure_threshold:
                    self._transition_to(CircuitState.OPEN)

    def _should_attempt_reset(self) -> bool:
        if self._last_failure_time is None:
            return True
        elapsed = time.monotonic() - self._last_failure_time
        return elapsed >= self.cfg.recovery_timeout

    def _seconds_until_retry(self) -> float:
        if self._last_failure_time is None:
            return 0.0
        elapsed = time.monotonic() - self._last_failure_time
        return max(0.0, self.cfg.recovery_timeout - elapsed)

    def _transition_to(self, new_state: CircuitState) -> None:
        old = self._state
        self._state         = new_state
        self._failure_count = 0
        self._success_count = 0
        logger.warning("[CB:%s] %s → %s", self.name,
                       old.value.upper(), new_state.value.upper())

    def stats(self) -> dict:
        return {
            "state":           self._state.value,
            "failure_count":   self._failure_count,
            "total_calls":     self._total_calls,
            "total_failures":  self._total_failures,
            "short_circuits":  self._total_short_circuits,
        }


class CircuitBreakerRegistry:
    """Registry global — um CircuitBreaker por serviço downstream.
    Instanciado uma vez no startup, compartilhado entre todos os requests."""

    def __init__(self):
        self._breakers: dict[str, CircuitBreaker] = {}

    def get(self, name: str, cfg=None) -> CircuitBreaker:
        if name not in self._breakers:
            self._breakers[name] = CircuitBreaker(name, cfg)
        return self._breakers[name]

    def stats(self) -> dict:
        return {n: cb.stats() for n, cb in self._breakers.items()}

circuit_registry = CircuitBreakerRegistry()

Camada 2

Bulkhead Isolation

O nome vem de navios: compartimentos estanques que isolam danos. Aqui, cada agente tem seu próprio pool de slots de concorrência. Se o agente de booking fica lento e esgota seus 10 slots, o agente de busca com seus 20 slots não é afetado.

Por que anyio.CapacityLimiter e não asyncio.Semaphore

asyncio.Semaphore funciona, mas anyio.CapacityLimiter expõe available_tokens e borrowed_tokens diretamente — essencial para métricas e healthcheck. Também é compatível com o modelo de cancelamento do anyio, que é mais robusto para timeout com move_on_after.

Implementação

python bulkhead.py 
import anyio
import logging
from dataclasses import dataclass
from typing import Callable, Any

logger = logging.getLogger(__name__)


@dataclass
class BulkheadConfig:
    max_concurrent: int   # slots simultâneos por agente
    timeout: float        # segundos antes de cancelar a execução


BULKHEAD_CONFIGS: dict[str, BulkheadConfig] = {
    "booking_agent":  BulkheadConfig(max_concurrent=10, timeout=30.0),
    "search_agent":   BulkheadConfig(max_concurrent=20, timeout=10.0),
    "payment_agent":  BulkheadConfig(max_concurrent=5,  timeout=15.0),
    "recovery_worker": BulkheadConfig(max_concurrent=3, timeout=120.0),
}


class BulkheadFullError(Exception):
    """Todos os slots estão ocupados. Request rejeitado imediatamente."""

class BulkheadTimeoutError(Exception):
    """Execução excedeu o timeout do bulkhead."""


class Bulkhead:
    def __init__(self, name: str, cfg: BulkheadConfig):
        self.name    = name
        self.cfg     = cfg
        self._limiter = anyio.CapacityLimiter(cfg.max_concurrent)

    @property
    def available_slots(self) -> int:
        return int(self._limiter.available_tokens)

    @property
    def borrowed_slots(self) -> int:
        return int(self._limiter.borrowed_tokens)

    async def run(self, fn: Callable, *args, **kwargs) -> Any:
        # Passo 1: tenta adquirir slot com timeout curto (2s).
        # Não queremos bloquear o caller esperando um slot — queremos falhar rápido.
        # move_on_after retorna sem erro se cancelado; verificamos scope.cancelled_caught.
        async with anyio.move_on_after(2.0) as slot_scope:
            async with self._limiter:
                # Passo 2: slot adquirido — executa com timeout da operação
                with anyio.move_on_after(self.cfg.timeout) as exec_scope:
                    result = await fn(*args, **kwargs)

                if exec_scope.cancelled_caught:
                    raise BulkheadTimeoutError(
                        f"[{self.name}] Timeout após {self.cfg.timeout}s"
                    )
                return result

        if slot_scope.cancelled_caught:
            raise BulkheadFullError(
                f"[{self.name}] Sem slots ({self.cfg.max_concurrent} em uso)"
            )


class BulkheadRegistry:
    def __init__(self):
        self._bulkheads: dict[str, Bulkhead] = {}

    def get(self, name: str) -> Bulkhead:
        if name not in self._bulkheads:
            cfg = BULKHEAD_CONFIGS.get(name, BulkheadConfig(10, 30.0))
            self._bulkheads[name] = Bulkhead(name, cfg)
        return self._bulkheads[name]

    def stats(self) -> dict:
        return {
            name: {
                "available": bh.available_slots,
                "in_use":    bh.borrowed_slots,
                "max":       bh.cfg.max_concurrent,
            }
            for name, bh in self._bulkheads.items()
        }

bulkhead_registry = BulkheadRegistry()
Camada 3

Retry com Exponential Backoff + Full Jitter

O backoff exponencial sozinho não resolve o problema do thundering herd: se 100 clientes falham ao mesmo tempo e todos esperam exatamente 2s antes de retentar, eles chegam de volta ao serviço no mesmo instante.

Full jitter resolve isso: delay = random(0, min(base * 2^attempt, max_delay)). Cada cliente espera um tempo aleatório dentro da janela exponencial, distribuindo o tráfego de retry ao longo do tempo.

Full Jitter vs Equal Jitter

Equal jitter: delay/2 + random(0, delay/2). Full jitter: random(0, delay). Full jitter distribui melhor sob carga alta porque a variância é maior — menos chance de colisão. AWS recomenda full jitter para retries em sistemas distribuídos.

Implementação

python retry.py 
import asyncio
import logging
import random
from dataclasses import dataclass
from typing import Callable, Any, Type

from circuit_breaker import CircuitBreaker, CircuitOpenError

logger = logging.getLogger(__name__)


@dataclass
class RetryConfig:
    max_attempts: int        = 3
    base_delay: float        = 1.0   # segundos — delay inicial
    max_delay: float         = 30.0  # teto do backoff
    exponential_base: float  = 2.0   # fator de crescimento
    jitter: bool             = True
    retryable_exceptions: tuple     = (Exception,)
    non_retryable_exceptions: tuple = ()


RETRY_CONFIGS: dict[str, RetryConfig] = {
    "hotel_api": RetryConfig(
        max_attempts=3, base_delay=1.0, max_delay=10.0,
        non_retryable_exceptions=(ValueError, KeyError),
    ),
    "payment_api": RetryConfig(
        max_attempts=2, base_delay=2.0, max_delay=10.0,
        non_retryable_exceptions=(ValueError,),
    ),
    "search_agent": RetryConfig(max_attempts=4, base_delay=0.5, max_delay=8.0),
}


def _calculate_delay(attempt: int, cfg: RetryConfig) -> float:
    # Exponential backoff: min(base * 2^attempt, max_delay)
    delay = min(cfg.base_delay * (cfg.exponential_base ** attempt), cfg.max_delay)
    # Full jitter: distribui retries ao longo do tempo — evita thundering herd
    return random.uniform(0, delay) if cfg.jitter else delay


async def with_retry(
    fn: Callable,
    *args,
    config: RetryConfig | None = None,
    circuit_breaker: CircuitBreaker | None = None,
    service_name: str = "unknown",
    **kwargs,
) -> Any:
    cfg = config or RetryConfig()
    last_exception: Exception | None = None

    for attempt in range(cfg.max_attempts):
        try:
            # Se circuit_breaker fornecido, envolve a chamada nele.
            # As falhas contadas pelo retry alimentam o CB automaticamente.
            if circuit_breaker:
                return await circuit_breaker.call(fn, *args, **kwargs)
            return await fn(*args, **kwargs)

        except CircuitOpenError:
            # CB aberto: não retenta, propaga imediatamente.
            # Retentar seria inútil — o CB vai rejeitar de qualquer forma.
            logger.warning("[retry:%s] Circuit OPEN na tentativa %d/%d. Abortando.",
                           service_name, attempt + 1, cfg.max_attempts)
            raise

        except cfg.non_retryable_exceptions as exc:
            # Erro de negócio (ex: hotel_id inválido) — não adianta retentar
            logger.warning("[retry:%s] Erro não-retentável (%s): %s",
                           service_name, type(exc).__name__, exc)
            raise

        except cfg.retryable_exceptions as exc:
            last_exception = exc
            if attempt == cfg.max_attempts - 1:
                logger.error("[retry:%s] Todas as %d tentativas falharam: %s",
                             service_name, cfg.max_attempts, exc)
                raise

            delay = _calculate_delay(attempt, cfg)
            logger.warning(
                "[retry:%s] Tentativa %d/%d falhou (%s). Aguardando %.2fs.",
                service_name, attempt + 1, cfg.max_attempts,
                type(exc).__name__, delay,
            )
            await asyncio.sleep(delay)

    raise last_exception  # type: ignore — satisfaz o type checker

Integração — retry × circuit breaker × idempotência

Os três mecanismos operam em camadas diferentes. É importante entender o que cada um cobre para não confundir responsabilidades:

LangGraph retoma o nó (recovery) └─► @idempotent_node evita que o efeito externo se duplique └─► Redis cache por hash(thread_id + node_name + key_fields) Dentro do nó, a chamada HTTP à API falha └─► with_retry() retenta a chamada HTTP └─► cada falha alimenta o CircuitBreaker automaticamente └─► quando CB abre, retry para imediatamente (CircuitOpenError)
Idempotência e retry são camadas distintas

@idempotent_node está na camada do nó LangGraph — protege contra reexecução do nó inteiro (recovery, restart). with_retry está dentro do nó — protege contra falha de uma chamada HTTP específica. Um não substitui o outro.

python nodes.py — uso composto 
# Ordem dos decorators importa:
# traced_node (fora) → captura tempo total incluindo idempotency check
# idempotent_node    → verifica cache antes de executar
# dentro do nó       → with_retry envolve a chamada HTTP

@traced_node("book_hotel", attributes={"agent.capability": "booking"})
@idempotent_node(redis, "book_hotel", key_fields=["hotel_id", "checkin", "checkout"])
async def book_hotel_node(state: AgentState, config: dict) -> dict:
    cb = circuit_registry.get("hotel_api", CIRCUIT_CONFIGS["hotel_api"])

    try:
        booking = await with_retry(
            hotel_api.create_booking,
            hotel_id=state["hotel_id"],
            checkin=state["checkin"],
            checkout=state["checkout"],
            config=RETRY_CONFIGS["hotel_api"],
            circuit_breaker=cb,
            service_name="hotel_api",
        )
        return {"booking_id": booking.id, "booking_status": "confirmed"}

    except CircuitOpenError:
        return {"booking_status": "unavailable",
                "error": "Hotel API indisponível temporariamente."}
    except Exception as exc:
        return {"booking_status": "error", "error": str(exc)}
Camada 4

Cascading Timeout Budget

O problema com timeouts independentes em cada agente: se Agente A tem timeout de 25s e chama Agente B com timeout de 20s, e B chama uma API com timeout de 15s — quando a API trava por 15s, B espera 20s, A já gastou 20s dos seus 25s e quase não tem tempo para processar a resposta.

A solução é propagar o budget restante da request original como header X-Timeout-Budget. Cada agente na cadeia usa o menor valor entre seu próprio timeout e o budget recebido.

Por que ContextVar e não parâmetro de função

O budget precisa estar disponível em qualquer ponto da cadeia de chamadas sem ser passado explicitamente por todos os intermediários. contextvars.ContextVar é thread-safe e funciona com asyncio — cada Task herda o contexto da Task pai, o que é exatamente o comportamento que queremos.

Implementação

python cascade_timeout.py 
import time
from contextvars import ContextVar

# ContextVar: disponível em qualquer ponto da cadeia sem ser passado explicitamente.
# Cada asyncio Task herda o contexto da Task pai.
_budget: ContextVar[float] = ContextVar("timeout_budget", default=30.0)
_start:  ContextVar[float] = ContextVar("request_start",  default=0.0)


def init_budget(total_seconds: float) -> None:
    """Chama no início de cada request — antes de qualquer chamada downstream."""
    _budget.set(total_seconds)
    _start.set(time.monotonic())


def remaining_budget() -> float:
    """Quanto tempo ainda resta para toda a cadeia desta request."""
    elapsed = time.monotonic() - _start.get()
    return max(0.0, _budget.get() - elapsed)


# ── No Agente A: injeta budget restante ao chamar Agente B ──────────────────
async def call_agent_b_with_budget(endpoint: str, payload: dict, token: str) -> dict:
    budget = remaining_budget()

    if budget < 1.0:
        raise TimeoutError("Budget esgotado antes de chamar Agente B")

    headers = {
        "Authorization":    f"Bearer {token}",
        "X-Timeout-Budget": str(budget),  # passa o budget restante
    }
    inject(headers)  # propaga trace context junto

    # httpx respeitará o budget como timeout da conexão
    async with httpx.AsyncClient(timeout=budget) as client:
        response = await client.post(endpoint, json=payload, headers=headers)
        response.raise_for_status()
        return response.json()


# ── No Agente B: extrai o budget recebido e inicializa localmente ────────────
@app.post("/invoke")
async def invoke(request: Request, body: InvokeRequest):
    # Herda o budget do chamador — não assume valor fixo
    budget = float(request.headers.get("X-Timeout-Budget", "10.0"))
    init_budget(budget)

    bulkhead = bulkhead_registry.get("search_agent")
    # Aplica o menor entre o timeout do bulkhead e o budget recebido
    bulkhead.cfg.timeout = min(bulkhead.cfg.timeout, budget)

    return await bulkhead.run(graph.ainvoke, body.input, ...)
Camada 5

Backpressure na Recovery Queue

Sem limite, uma rajada de falhas de ECS tasks (spot interruption, deploy em cascata) pode enfileirar dezenas de threads órfãos simultaneamente na recovery:queue. O Redis acumula indefinidamente. O Recovery Worker, processando um por vez, nunca alcança o final da fila.

A solução é limitar o tamanho da fila via Lua script atômico. Overflow vai direto para a DLQ — o operador vê o alarme e age. Preferimos perder a retomada automática de alguns threads a deixar o Redis explodir sob pressão.

Lua script atômico — por que não pipeline Python

Por que Lua e não LLEN + RPUSH em pipeline

Um pipeline Redis executa os comandos em sequência, mas entre o LLEN e o RPUSH outro cliente pode inserir um item — race condition. O Lua script é executado atomicamente no Redis: nenhuma outra operação acontece entre o LLEN e o RPUSH. É a única forma de garantir o teto da fila sem locks externos.

python recovery_worker.py — QueueGuard 
QUEUE_MAX_SIZE       = int(os.getenv("RECOVERY_QUEUE_MAX_SIZE", "100"))
QUEUE_WARN_THRESHOLD = float(os.getenv("RECOVERY_QUEUE_WARN_THRESHOLD", "0.7"))

class QueueGuard:
    def __init__(self, redis, dlq: "DLQManager"):
        self.redis = redis
        self.dlq   = dlq

    async def safe_enqueue(self, thread_id: str) -> bool:
        # Lua garante atomicidade do check + enqueue.
        # Sem isso: dois workers podem ambos ler size=99, ambos inserir, fila vai a 101.
        script = """
        local size = redis.call('LLEN', KEYS[1])
        if size >= tonumber(ARGV[1]) then
            return 0
        end
        redis.call('RPUSH', KEYS[1], ARGV[2])
        return 1
        """
        result = await self.redis.eval(
            script,
            1,                           # número de KEYS
            config.recovery_queue_key,   # KEYS[1]
            QUEUE_MAX_SIZE,              # ARGV[1]
            thread_id,                   # ARGV[2]
        )

        if result == 0:
            # Fila cheia — vai direto para DLQ com reason específico
            logger.error("Fila cheia (%d itens). Thread %s → DLQ.",
                         QUEUE_MAX_SIZE, thread_id)
            await self.dlq.send_to_dlq(
                thread_id,
                reason="queue_full",
                error=f"recovery:queue atingiu limite de {QUEUE_MAX_SIZE} itens",
            )
            return False

        # Alerta se utilização acima de 70%
        current = await self.redis.llen(config.recovery_queue_key)
        util    = current / QUEUE_MAX_SIZE
        if util >= QUEUE_WARN_THRESHOLD:
            logger.warning("Fila em %.0f%% da capacidade (%d/%d).",
                           util * 100, current, QUEUE_MAX_SIZE)
        return True

from fastapi import FastAPI, HTTPException
from circuit_breaker import circuit_registry, CircuitOpenError
from bulkhead import bulkhead_registry, BulkheadFullError, BulkheadTimeoutError
from cascade_timeout import init_budget

app = FastAPI()


@app.post("/agents/booking/invoke")
async def booking_invoke(body: InvokeRequest, request: Request):
    # Herda o budget do chamador ou usa o default (30s)
    budget = float(request.headers.get("X-Timeout-Budget", "30.0"))
    init_budget(budget)

    # Circuit Breaker primeiro — falha imediata se serviço degradado.
    # Evita consumir slot do bulkhead com chamada que vai falhar de qualquer forma.
    cb = circuit_registry.get("booking_agent")
    bulkhead = bulkhead_registry.get("booking_agent")

    try:
        # Bulkhead envolve o cb.call — limite de concorrência aplicado aqui
        result = await bulkhead.run(
            cb.call,
            graph.ainvoke,
            body.input,
            config={"configurable": {"thread_id": body.thread_id}},
        )
        return result

    except CircuitOpenError:
        raise HTTPException(status_code=503,
            detail="Serviço degradado. Tente novamente em instantes.")
    except BulkheadFullError:
        raise HTTPException(status_code=503,
            detail="Capacidade esgotada. Tente novamente.")
    except BulkheadTimeoutError:
        raise HTTPException(status_code=504,
            detail="Timeout ao processar sua solicitação.")


@app.get("/health")
async def health():
    cb_stats  = circuit_registry.stats()
    bh_stats  = bulkhead_registry.stats()
    any_open  = any(s["state"] == "open" for s in cb_stats.values())

    return JSONResponse(
        content={"circuits": cb_stats, "bulkheads": bh_stats},
        status_code=503 if any_open else 200,
    )

import pytest, asyncio
from circuit_breaker import CircuitBreaker, CircuitBreakerConfig, CircuitOpenError

@pytest.fixture
def cb():
    return CircuitBreaker("test", CircuitBreakerConfig(
        failure_threshold=3,
        success_threshold=2,
        recovery_timeout=0.1,  # curto para não travar o teste
    ))

async def failing_fn(): raise Exception("erro")
async def ok_fn(): return "ok"


@pytest.mark.asyncio
async def test_opens_after_threshold(cb):
    for _ in range(3):
        with pytest.raises(Exception): await cb.call(failing_fn)
    assert cb.state.value == "open"


@pytest.mark.asyncio
async def test_short_circuits_when_open(cb):
    for _ in range(3):
        with pytest.raises(Exception): await cb.call(failing_fn)
    # ok_fn nem é tentada — CircuitOpenError imediato
    with pytest.raises(CircuitOpenError): await cb.call(ok_fn)


@pytest.mark.asyncio
async def test_half_open_after_timeout(cb):
    for _ in range(3):
        with pytest.raises(Exception): await cb.call(failing_fn)
    await asyncio.sleep(0.15)      # aguarda recovery_timeout
    result = await cb.call(ok_fn)  # HALF_OPEN — permite 1 chamada de teste
    assert result == "ok"


@pytest.mark.asyncio
async def test_closes_after_success_threshold(cb):
    for _ in range(3):
        with pytest.raises(Exception): await cb.call(failing_fn)
    await asyncio.sleep(0.15)
    await cb.call(ok_fn)  # sucesso 1
    await cb.call(ok_fn)  # sucesso 2 → success_threshold atingido → CLOSED
    assert cb.state.value == "closed"
