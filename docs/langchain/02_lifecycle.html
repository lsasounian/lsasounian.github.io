Componentes do sistema

AgentHeartbeat

Sinal de vida

Context manager que renova heartbeat:{thread_id} a cada 10s com TTL de 30s. Se o processo morre, a chave expira naturalmente.

OrphanScanner

Detector de órfãos

Varre threads:in_progress a cada 20s. Threads sem heartbeat são considerados órfãos e enfileirados para recovery.

RecoveryConsumer

Executor de retomada

BLPOP na recovery queue. Chama aget_state() para verificar nós pendentes, depois ainvoke(None) para retomar.

DLQManager

Dead-letter queue

Conta tentativas por thread. Após MAX_ATTEMPTS, move para DLQ com metadados: reason, error, timestamp, attempts.

Estrutura de chaves no Redis

threads:in_progress SET thread_ids que foram iniciados e não terminaram
heartbeat:{thread_id} STRING ECS task ID · TTL 30s · renovado a cada 10s
recovery:queue LIST fila principal · máx 100 itens · Lua atômico
recovery:attempts:{thread_id} STRING contador de tentativas · TTL 24h
recovery:dlq LIST threads que esgotaram tentativas · intervenção manual
recovery:dlq:meta:{thread_id} HASH reason · error · attempts · failed_at
lock:thread:{thread_id} STRING distributed lock · SET NX · TTL 120s

Heartbeat — implementação

class AgentHeartbeat:
    async def _beat(self):
        # Renova com TTL curto — se o processo morre, a chave expira
        await self.redis.setex(
            f"heartbeat:{self.thread_id}",
            30,          # TTL segundos
            self.task_id  # identifica qual ECS task está rodando
        )

Fluxo DLQ — decisão após falha

consume_one(thread_id) falha
   │
   ▼
handle_failure(thread_id, reason, error)
   │
   ├── increment_attempts() → attempts = N
   │
   ├── N < MAX_ATTEMPTS → rpush(recovery:queue) ← reenfileira
   │
   └── N >= MAX_ATTEMPTS → send_to_dlq()
                      ├── rpush(recovery:dlq, thread_id)
                      ├── hset(recovery:dlq:meta, {reason, error, attempts, failed_at})
                      └── delete(recovery:attempts:thread_id)
