Multi-Agent AWS · Padrões de Sistema

Consistência
de estado

Três garantias que protegem o estado do LangGraph quando múltiplas instâncias competem pelo mesmo thread ou quando o schema evolui.

Sem lock distribuído:
Request A ──────────────────────────► invoke(thread_123)
Request B ──────────► invoke(thread_123)
                          │
            Ambos leem o checkpoint    →   estado corrompido

Com lock distribuído:
Request A ──► adquire lock ──────────────────► executa ──► libera
Request B ──► aguarda lock ───────────────────────────────────────► executa

Três pilares

01

Distributed Lock

Redis SET NX com Lua script atômico garante que apenas uma instância executa por thread_id. Renovação automática do TTL para execuções longas.

02

Idempotência de nós

Cache por hash(thread_id + node_name + key_fields). Resultado armazenado no Redis com TTL 24h. Retry ou recovery não duplica efeito externo.

03

Versionamento de schema

Campo schema_version no estado + migration chain. Checkpoints v1 migram automaticamente para v2 antes de qualquer nó executar.

Quais nós precisam de idempotência

Tipo de nó Precisa? Motivo
Leitura / busca não sem efeito externo — pode repetir
Decisão / roteamento não determinístico pelo estado
LLM call opcional economia de tokens + consistência de resposta
Escrita em banco próprio sim duplicata causa inconsistência
POST em API externa sim efeito colateral irreversível
Cobrança / pagamento sim cobrança dupla é inaceitável
Envio de email / push sim duplicata visível ao usuário
Reserva / booking sim reserva dupla causa prejuízo real

Distributed lock — Lua script

# Check-and-delete atômico — evita deletar lock de outra instância
script = """
if redis.call("get", KEYS[1]) == ARGV[1] then
    return redis.call("del", KEYS[1])
else
    return 0  -- não era nosso lock
end
"""

# Aquisição com SET NX EX
ok = await redis.set(
    f"lock:thread:{thread_id}",
    lock_value,      # UUID único desta aquisição
    nx=True,         # só cria se não existir
    ex=120,          # TTL: tempo máximo de execução
)

Migration chain — schema evolution

v1 → estado base: messages, destination
v2 → adiciona budget: 0.0 (default para estados v1)
v3 → adiciona preferred_currency: "USD"
v4 → adiciona loyalty_tier: "standard" 
# Nó __coerce__ roda no entry point do grafo
def coerce_state(state):
    version = state.get("schema_version", 1)
    while version < CURRENT_VERSION:
        migration = MIGRATIONS[version]  # dict: versão → lambda
        state = migration(state)
        version = state["schema_version"]
    return state

# Checkpoint v1 do Redis passa por v1→v2→v3→v4
# antes de qualquer nó de negócio executar

Idempotência — duas camadas

Decorator @idempotent_node protege o LangGraph — evita que o nó execute ação externa duas vezes.
idempotency_key na API externa protege o downstream — Stripe, Adyen e outras APIs suportam este padrão nativamente. 
@traced_node("charge_card")
@idempotent_node(redis, "charge_card",
    key_fields=["booking_id", "amount", "currency"])
async def charge_card_node(state, config):
    # key_fields → hash determinístico por ação específica
    # mesmo estado em volta → mesma chave → resultado cacheado

    charge = await payment_api.charge(
        booking_id=state["booking_id"],
        amount=state["amount"],
        idempotency_key=state["booking_id"],  # ← API externa
    )
    return {"charge_id": charge.id}
