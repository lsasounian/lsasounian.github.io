Três estratégias

Blue / Green
CodeDeploy · 2 Target Groups
✓Rollback instantâneo (troca de TG)
✓Smoke tests antes de trocar tráfego
✓Melhor para multi-cluster
✗Custo: dobra tasks durante deploy
✗Maior complexidade de infra
Canary
CodeDeploy · weighted routing
✓Rollback automático por alarme
✓Progressão controlada (10% → 100%)
✓Valida performance em produção
✗Custo alto durante canary
✗Não para breaking changes A2A
Rolling
ECS nativo · sem CodeDeploy
✓Baixo custo (+33% tasks temporário)
✓Sem infra extra
✓Circuit breaker nativo do ECS
✗Rollback mais lento
✗Sem controle de ordem multi-cluster

Multi-cluster — ordem de deploy

Regra fundamental: deploy do consumidor antes do produtor. O serviço que consome a API deve aceitar a nova versão do contrato antes do produtor começar a emiti-la.

Passo 1: Deploy search-agent v2 (suporta v1 e v2 simultaneamente)
         booking-agent v1 continua chamando → recebe respostas v1 ✓

Passo 2: Valida search-agent v2 por 15-30min (métricas, error rate)

Passo 3: Deploy booking-agent v2 (passa X-API-Version: v2)
         search-agent v2 responde com v2 ✓

Passo 4: Deploy search-agent v2.1 (remove suporte a v1)

NLB vs ALB

# ALB — use para tráfego externo e entre agentes HTTP/REST
# Suporta: weighted routing, path rules, header-based routing
# Necessário para: Blue/Green e Canary com CodeDeploy

# NLB — use para comunicação A2A interna de baixa latência
# Suporta: TCP, gRPC direto, menor latência
# Não suporta: weighted routing → Blue/Green via DNS swap (Route 53)

# Recomendação para multi-agent:
# ALB externo  → usuário → agente (HTTP REST, Blue/Green via CodeDeploy)
# NLB interno  → agente → agente (gRPC A2A, menor latência)
Recomendação: Blue/Green para releases com mudança de schema A2A ou breaking changes. Canary para features novas sem impacto em contrato. Rolling apenas para hotfixes urgentes onde o risco de inconsistência de checkpoint é aceitável.

Graceful shutdown — ECS Task Definition

# Terraform — tempos que protegem checkpoints ativos
resource "aws_ecs_service" "agent" {
  stop_timeout = 120  # segundos após SIGTERM antes de SIGKILL
                       # deve ser >= tempo máximo de execução do agente
}

resource "aws_lb_target_group" "agent" {
  deregistration_delay = 120  # ALB drena conexões existentes
                               # antes de remover o target
  health_check {
    path                = "/health"
    healthy_threshold   = 2
    unhealthy_threshold = 3
    interval            = 10
  }
}
