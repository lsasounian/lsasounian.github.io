Lock, Idempotência & Schema

Três garantias que protegem o estado LangGraph: lock distribuído por thread_id, idempotência de nós com efeito externo, e versionamento de schema com migration chain.

Contexto

Os três problemas de consistência

Em um sistema multi-agent com LangGraph e RedisSaver, três classes distintas de problema de consistência podem surgir — cada uma exige um mecanismo diferente:

Problema 1: Race condition no checkpoint
Request A e Request B chegam com o mesmo thread_id
  └─► Ambos leem o checkpoint simultaneamente
  └─► Ambos modificam o estado
  └─► Último a escrever "ganha" → estado corrompido
  └─► Solução: Distributed Lock (SET NX por thread_id)

Problema 2: Efeito externo duplicado
Nó book_hotel executa, reserva feita, ECS task morre antes do próximo checkpoint
  └─► Recovery Worker retoma → LangGraph reexecuta book_hotel
  └─► Reserva duplicada
  └─► Solução: @idempotent_node (cache por hash do input)

Problema 3: Schema incompatível
Checkpoint v1 existe no Redis: {messages, destination}
Código atualizado para v2: AgentState agora exige {messages, destination, budget}
  └─► Grafo carrega checkpoint v1 → KeyError ou comportamento incorreto
  └─► Solução: campo schema_version + migration chain no nó __coerce__

Pilar 1

Distributed Lock

O RedisSaver não tem locking nativo. Se dois requests chegam com o mesmo thread_id — seja por retry do cliente, seja por dois agentes A2A chamando o mesmo thread — ambos podem ler o checkpoint, modificar o estado em paralelo, e o último a escrever sobrescreve o outro.

Por que Redis SET NX e não asyncio.Lock

asyncio.Lock existe apenas na memória do processo. Com múltiplos ECS tasks (o caso normal em produção), cada task tem seu próprio lock — o lock não é distribuído. Redis SET NX é atômico no servidor Redis e visível por todos os processos que compartilham o mesmo Redis.

Implementação com SET NX e Lua script

distributed_lock.py PYTHON 
import asyncio
import uuid
import redis.asyncio as aioredis
from contextlib import asynccontextmanager


class LockTimeoutError(Exception):
    """Não foi possível adquirir o lock dentro do timeout."""


class RedisThreadLock:
    def __init__(self, redis: aioredis.Redis, ttl: int = 120):
        self.redis = redis
        self.ttl   = ttl  # deve ser > tempo máximo de execução do agente

    @asynccontextmanager
    async def acquire(self, thread_id: str, timeout: float = 5.0):
        lock_key   = f"lock:thread:{thread_id}"
        # UUID único por aquisição: garante que só quem adquiriu o lock pode liberar.
        # Sem isso, uma instância poderia liberar o lock de outra.
        lock_value = str(uuid.uuid4())
        acquired   = False
        deadline   = asyncio.get_event_loop().time() + timeout

        while asyncio.get_event_loop().time() < deadline:
            # SET NX EX: atômico — só seta se a chave não existir.
            # Se existir (outro processo tem o lock), retorna None.
            ok = await self.redis.set(
                lock_key, lock_value,
                nx=True,    # NX: Not eXists
                ex=self.ttl, # TTL: evita lock eterno em caso de crash
            )
            if ok:
                acquired = True
                break
            await asyncio.sleep(0.1)  # backoff simples entre tentativas

        if not acquired:
            raise LockTimeoutError(
                f"Thread {thread_id} está sendo processado por outra instância"
            )

        try:
            yield
        finally:
            # Lua script: check-and-delete atômico.
            # Sem atomicidade: processo A verifica que é seu lock, processo B expira e
            # recria, processo A deleta o lock do processo B. Corrompido.
            # Com Lua: verificação e deleção acontecem atomicamente no Redis.
            script = """
            if redis.call("get", KEYS[1]) == ARGV[1] then
                return redis.call("del", KEYS[1])
            else
                return 0
            end
            """
            await self.redis.eval(script, 1, lock_key, lock_value)


# Instância global — compartilhada entre requests
thread_lock = RedisThreadLock(redis, ttl=120)
app.py — uso do lock PYTHON 
@app.post("/agents/invoke")
async def invoke(body: InvokeRequest):
    try:
        async with thread_lock.acquire(body.thread_id, timeout=5.0):
            # Dentro do lock: garantia de que apenas este processo
            # está executando este thread_id no momento
            result = await run_agent(body.thread_id, body.input)
            return result
    except LockTimeoutError:
        raise HTTPException(
            status_code=409,
            detail="Este thread já está sendo processado. Tente novamente."
        )

Renovação automática para execuções longas

Se um agente pode levar mais tempo que o TTL do lock (ex: processamento de documentos longos), o lock expira antes de terminar — e outra instância pode adquirir o mesmo lock enquanto a primeira ainda está rodando.

distributed_lock.py — renovação PYTHON 
@asynccontextmanager
async def acquire_with_renewal(self, thread_id: str, timeout: float = 5.0):
    lock_key   = f"lock:thread:{thread_id}"
    lock_value = str(uuid.uuid4())
    # ... aquisição igual ao anterior ...

    async def renew():
        # Renova na metade do TTL para ter margem de segurança.
        # Se o processo trava (deadlock, GC pause longa), para de renovar
        # e o TTL expira naturalmente — lock liberado automaticamente.
        while True:
            await asyncio.sleep(self.ttl * 0.5)
            await self.redis.expire(lock_key, self.ttl)

    renew_task = asyncio.create_task(renew())
    try:
        yield
    finally:
        renew_task.cancel()
        await self._safe_release(lock_key, lock_value)
Pilar 2

Idempotência de nós

O LangGraph pode executar um nó mais de uma vez para o mesmo input em dois cenários: retry após falha de rede, e recovery após crash do ECS task. Se esse nó faz uma chamada externa com efeito colateral — cobrar cartão, criar reserva, enviar email — a reexecução causa dano real.

O checkpoint garante onde o grafo estava, não o que aconteceu no mundo

O RedisSaver salva o estado do grafo. Mas se o ECS task morre após a reserva ser criada e antes do próximo checkpoint ser salvo, o grafo vai retomar e reexecutar o nó de reserva — a reserva já existe no sistema externo mas o LangGraph não sabe. O @idempotent_node resolve isso na camada do nó, sem depender de quando o checkpoint foi salvo.

Geração da chave de idempotência

A chave combina três elementos: thread_id (isola por conversa), node_name (isola por nó), e um hash dos campos relevantes do estado (key_fields). O hash garante que o mesmo nó com inputs diferentes gera chaves diferentes.

Por que key_fields e não o estado inteiro

O estado LangGraph pode conter uma lista de mensagens que cresce a cada turno. Usar o estado inteiro no hash significa que a mesma ação com estados diferentes (mensagens acumuladas) geraria chaves diferentes — quebrando a proteção. key_fields define quais campos determinam a unicidade da ação — geralmente os parâmetros da chamada externa, não o histórico.

idempotency.py PYTHON 
import hashlib
import json
from functools import wraps
import redis.asyncio as aioredis

IDEMPOTENCY_TTL = 60 * 60 * 24  # 24h — janela de proteção contra duplicatas


def _make_key(thread_id: str, node_name: str, state: dict) -> str:
    # json.dumps com sort_keys=True garante que a mesma dict sempre gera o mesmo JSON
    # independente da ordem de inserção das chaves.
    # default=str converte tipos não-serializáveis (datetime, UUID) para string.
    state_bytes = json.dumps(state, sort_keys=True, default=str).encode()
    state_hash  = hashlib.sha256(state_bytes).hexdigest()[:16]
    return f"idempotency:{thread_id}:{node_name}:{state_hash}"

Decorator completo

idempotency.py — decorator PYTHON 
def idempotent_node(
    redis: aioredis.Redis,
    node_name: str,
    key_fields: list[str] | None = None,
    ttl: int = IDEMPOTENCY_TTL,
):
    def decorator(func):
        @wraps(func)
        async def wrapper(state: dict, *args, **kwargs):
            config    = kwargs.get("config", {})
            thread_id = config.get("configurable", {}).get("thread_id", "unknown")

            # Extrai apenas os campos relevantes para o hash.
            # Se key_fields=None, usa o estado inteiro (mais seguro, menos eficiente).
            relevant = (
                {k: state.get(k) for k in key_fields if k in state}
                if key_fields else state
            )
            idempotency_key = _make_key(thread_id, node_name, relevant)

            # Verifica cache: se resultado já existe, retorna sem executar
            cached = await redis.get(idempotency_key)
            if cached:
                logger.info("[idempotent] Nó '%s' já executado para '%s'. Cache hit.",
                            node_name, thread_id)
                return json.loads(cached)

            # Executa a ação externa
            result = await func(state, *args, **kwargs)

            # Persiste resultado com TTL.
            # default=str para tipos não-serializáveis no resultado.
            await redis.setex(
                idempotency_key,
                ttl,
                json.dumps(result, default=str),
            )
            return result
        return wrapper
    return decorator

Duas camadas de idempotência

O decorator protege o LangGraph — evita que o nó execute a ação externa duas vezes. Mas se a API externa também não for idempotente, existe uma janela de race condition: o request chega à API, ela processa, mas a resposta se perde antes de voltar ao agente.

Sem idempotency key na API externa:
  POST /charge → API processa → resposta se perde
  Retry POST /charge → API processa DE NOVO → cobrança dupla
  Redis cache não ajuda — o retry aconteceu antes de salvar o resultado

Com idempotency key em ambas as camadas:
  POST /charge + Idempotency-Key: booking-123 → API processa → salva associação
  Retry POST /charge + Idempotency-Key: booking-123 → API retorna resultado anterior
  Redis cache: nó não é reexecutado se já salvou o resultado
nodes.py — duas camadas PYTHON 
@traced_node("charge_card")
@idempotent_node(redis, "charge_card",
    key_fields=["booking_id", "amount", "currency"])
async def charge_card_node(state: AgentState, config: dict) -> dict:
    # Camada 1: @idempotent_node verifica o cache Redis antes de executar.
    # Se já executou, retorna o charge_id cacheado sem chamar a API.

    # Camada 2: idempotency_key na API externa protege contra o caso em que
    # a resposta da API se perde antes de salvar no Redis.
    # Stripe, Adyen, Braintree suportam este header nativamente.
    idempotency_key = f"{state['booking_id']}:{state['amount']}"

    charge = await payment_api.charge(
        booking_id=state["booking_id"],
        amount=state["amount"],
        currency=state["currency"],
        idempotency_key=idempotency_key,  # header Idempotency-Key
    )
    return {"charge_id": charge.id, "payment_status": "paid"}

Pilar 3

Versionamento de Schema

O LangGraph não tem migração nativa de checkpoints. Quando você evolui o AgentState — adiciona um campo, renomeia, muda tipo — checkpoints antigos no Redis ficam incompatíveis com o novo código.

Sintomas de incompatibilidade de schema

KeyError silencioso (campo ausente tratado como None), comportamento incorreto por campo com tipo errado, ou exceção na desserialização do checkpoint. Nenhum deles é óbvio na stack trace — o erro parece ser do nó, não do schema.

Estratégias de migração

EstratégiaComo funcionaQuando usarLimitação
Versão no thread_idv2::thread-123 — threads antigos ficam no namespace v1Breaking change que aceita reiniciar conversas ativasThreads em andamento na v1 não migram
schema_version + migration chainCampo no estado + nó __coerce__ que migra progressivamenteMigração transparente de checkpoints existentesCódigo de migration precisa ser mantido
Campos opcionaisNovos campos como Optional[tipo] com defaultAdições simples sem lógica de migraçãoNão serve para renames ou mudanças de tipo

Migration chain com nó __coerce__

O nó __coerce__ é adicionado como entry point do grafo. Ele roda antes de qualquer nó de negócio e garante que o estado sempre está na versão atual, independente de qual versão estava no checkpoint.

state.py PYTHON 
from typing import TypedDict, Optional
from langchain_core.messages import BaseMessage

class AgentState(TypedDict):
    schema_version:     int                   # sempre presente — identifica a versão
    messages:           list[BaseMessage]
    destination:        str
    budget:             Optional[float]        # adicionado em v2 — Optional para compat v1
    preferred_currency: Optional[str]          # adicionado em v3
    loyalty_tier:       Optional[str]          # adicionado em v4
migrations.py PYTHON 
from typing import Callable

# Cada entrada é: versão_atual → função que produz versão_atual+1
# A função recebe o estado como dict e retorna o estado migrado.
MIGRATIONS: dict[int, Callable[[dict], dict]] = {
    1: lambda s: {**s, "budget": 0.0,  "schema_version": 2},
    2: lambda s: {**s, "preferred_currency": "USD", "schema_version": 3},
    3: lambda s: {**s, "loyalty_tier": "standard", "schema_version": 4},
}
CURRENT_VERSION = 4


def coerce_state(state: dict, config: dict) -> dict:
    """
    Nó __coerce__: garante que o estado está na versão atual antes de qualquer nó de negócio.
    Um checkpoint v1 passa por v1→v2→v3→v4 em sequência.
    Se a versão já é a atual, retorna sem modificação.
    """
    version = state.get("schema_version", 1)  # default 1 para estados sem versão

    while version < CURRENT_VERSION:
        migration = MIGRATIONS.get(version)
        if not migration:
            raise ValueError(f"Sem migration para versão {version}")
        state   = migration(state)
        version = state["schema_version"]

    return state
graph.py — entry point PYTHON 
from langgraph.graph import StateGraph, END
from langgraph.checkpoint.redis import RedisSaver
from migrations import coerce_state
from nodes import router_node, search_hotels_node, book_hotel_node, charge_card_node


def build_graph(checkpointer: RedisSaver):
    graph = StateGraph(AgentState)

    # __coerce__ é o entry point — garante migração antes de qualquer nó de negócio.
    # Ao retomar um checkpoint v1, este nó roda primeiro e migra o estado.
    graph.add_node("__coerce__", coerce_state)
    graph.add_node("router",      router_node)
    graph.add_node("search",      search_hotels_node)
    graph.add_node("book",        book_hotel_node)
    graph.add_node("charge",      charge_card_node)

    graph.set_entry_point("__coerce__")
    graph.add_edge("__coerce__", "router")
    # ... demais edges ...

    return graph.compile(checkpointer=checkpointer)
Quando remover código de migration antigo

Só remova uma entrada de MIGRATIONS quando tiver certeza de que não existem mais checkpoints com aquela versão no Redis. Na prática: aguarde o TTL dos checkpoints expirar (geralmente 7-30 dias dependendo da config do RedisSaver), ou faça um scan e verifique que nenhum checkpoint tem schema_version < versão_minima.

import pytest
from unittest.mock import AsyncMock
import fakeredis.aioredis as fakeredis
from idempotency import idempotent_node

@pytest.mark.asyncio
async def test_idempotent_node_caches_result():
    redis      = fakeredis.FakeRedis(decode_responses=True)
    call_count = 0

    @idempotent_node(redis, "charge_card", key_fields=["booking_id", "amount"])
    async def charge_node(state, config):
        nonlocal call_count
        call_count += 1
        return {"charge_id": "charge-abc"}

    state  = {"booking_id": "b-123", "amount": 500.0}
    config = {"configurable": {"thread_id": "t-001"}}

    result1 = await charge_node(state, config=config)
    result2 = await charge_node(state, config=config)  # simula retry

    assert call_count == 1           # ação executou só uma vez
    assert result1 == result2        # mesmo resultado nas duas chamadas
    assert result1["charge_id"] == "charge-abc"

@pytest.mark.asyncio
async def test_lock_prevents_concurrent_execution():
    import asyncio
    redis    = fakeredis.FakeRedis(decode_responses=True)
    from distributed_lock import RedisThreadLock
    lock     = RedisThreadLock(redis, ttl=10)
    executed = []

    async def task(name):
        async with lock.acquire("thread-x", timeout=3.0):
            executed.append(name)
            await asyncio.sleep(0.1)

    # Duas tasks tentam adquirir o mesmo lock
    # Devem executar em sequência, nunca em paralelo
    await asyncio.gather(task("A"), task("B"))
    assert len(executed) == 2  # ambas executaram
    assert executed[0] != executed[1]  # em sequência — não simultâneo
