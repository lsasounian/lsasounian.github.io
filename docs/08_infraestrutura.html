Por que um Redis compartilhado entre todos os serviços

O Recovery Worker precisa acessar os checkpoints criados pelo Agent — e o agente precisa acessar o lock criado pelo próprio processo. Redis separado por serviço quebraria o lifecycle inteiro: heartbeats, locks, recovery queue e checkpoints LangGraph precisam ser visíveis por todos os processos que participam do sistema. Um único ElastiCache com namespacing por chave é o design correto.

Design

Princípios de design da infraestrutura

PrincípioAplicação
Uma imagem, múltiplos serviçosAgent e Recovery Worker usam a mesma imagem ECR. O comportamento é definido pelo command no task definition.
Sem CMD no DockerfileO entrypoint é definido no ECS task definition via command. Facilita override sem rebuild de imagem.
Sidecar por taskX-Ray Daemon roda como container sidecar no mesmo task — acessível via localhost:4317 sem configuração de rede adicional.
Secrets via Secrets ManagerCLIENT_SECRET e chave privada RSA nunca em variáveis de ambiente plaintext — referenciados via ARN no task definition.
Least privilege por serviçoCada ECS Service tem seu próprio IAM Task Role com apenas as permissões que precisa.
VPC EndpointsECR, Secrets Manager, CloudWatch e X-Ray acessados via VPC Endpoints — sem tráfego saindo para a internet pública.

Por que um Recovery Worker por cluster e não um global

O Recovery Worker de um cluster precisa chamar graph.ainvoke() com o mesmo grafo compilado que os agentes daquele cluster usam. Um worker global precisaria conhecer todos os grafos — acoplamento indesejado. Um worker por cluster garante que ele usa exatamente o mesmo grafo, checkpointer e configuração dos agentes que monitora.

Uma imagem, comportamento diferente por command

O command no ECS task definition sobrescreve o CMD do Dockerfile. Isso permite usar a mesma imagem para o Agent e o Recovery Worker — mesmo código, entrypoint diferente.

ECR: 123456789.dkr.ecr.us-east-1.amazonaws.com/agent:v2.1.0 │ ├── booking-agent task definition │ command: ["python", "app.py"] │ → FastAPI sobe, escuta :8000, processa requests │ └── recovery-worker task definition command: ["python", "recovery_worker.py"] → OrphanScanner + RecoveryConsumer + QueueMonitor iniciam

Dockerfile — sem CMD fixo

dockerfileDockerfile
FROM python:3.12-slim

WORKDIR /app

# Instala dependências primeiro — maximiza cache de layer
COPY requirements.txt .
RUN pip install -r requirements.txt --no-cache-dir

# Copia código depois — layer invalidada só quando código muda
COPY . .

# Sem CMD: o command[] do ECS task definition define o entrypoint.
# Permite usar a mesma imagem para app.py e recovery_worker.py
# sem manter dois Dockerfiles sincronizados.

# Health check no nível do container — ECS usa isso para substituição de tasks
# Porta 8000 para agent; recovery_worker não expõe porta (script, não servidor)
HEALTHCHECK --interval=10s --timeout=3s --retries=3 \
  CMD python -c "import httpx; httpx.get('http://localhost:8000/health')" || exit 1
Task Definitions

Agent Task Definition

hclterraform/task_agent.tf
resource "aws_ecs_task_definition" "agent" {
  family                   = "booking-agent"
  requires_compatibilities = ["FARGATE"]
  network_mode             = "awsvpc"
  cpu                      = "1024"  # 1 vCPU
  memory                   = "2048"  # 2 GB
  task_role_arn            = aws_iam_role.agent_task_role.arn
  execution_role_arn       = aws_iam_role.ecs_execution_role.arn

  container_definitions = jsonencode([
    # Container principal: o agente
    {
      name      = "agent"
      image     = "${aws_ecr_repository.app.repository_url}:${var.image_tag}"
      command   = ["python", "app.py"]
      essential = true

      # stopTimeout: segundos entre SIGTERM e SIGKILL
      # Deve ser >= tempo máximo de execução de um agente
      stopTimeout = 120

      portMappings = [{ containerPort = 8000, protocol = "tcp" }]

      environment = [
        { name = "REDIS_URL",         value = "redis://${aws_elasticache_cluster.main.cache_nodes[0].address}:6379" },
        { name = "SERVICE_NAME",      value = "booking-agent" },
        { name = "OTLP_ENDPOINT",     value = "http://localhost:4317" },
        { name = "ENVIRONMENT",       value = var.environment },
        { name = "TRACE_SAMPLE_RATE", value = "0.1" },
      ]

      # Secrets via Secrets Manager — nunca plaintext em environment
      secrets = [
        { name = "CLIENT_SECRET",   valueFrom = aws_secretsmanager_secret.client_secret.arn },
        { name = "AUTH_SERVICE_URL", valueFrom = aws_secretsmanager_secret.auth_url.arn },
      ]

      logConfiguration = {
        logDriver = "awslogs"
        options = {
          "awslogs-group"         = "/ecs/booking-agent"
          "awslogs-region"        = var.aws_region
          "awslogs-stream-prefix" = "ecs"
        }
      }

      healthCheck = {
        command     = ["CMD-SHELL", "curl -f http://localhost:8000/health || exit 1"]
        interval    = 10
        timeout     = 5
        retries     = 3
        startPeriod = 30
      }
    },

    # Container sidecar: X-Ray Daemon
    # Recebe spans OTLP gRPC do agente via localhost:4317
    # Repassa para a API do X-Ray
    {
      name      = "xray-daemon"
      image     = "amazon/aws-xray-daemon:latest"
      essential = false  # falha do sidecar não derruba o container principal

      portMappings = [
        { containerPort = 4317, protocol = "tcp" },  # OTLP gRPC
        { containerPort = 2000, protocol = "udp" },  # X-Ray nativo (SDK legado)
      ]

      # cpu/memory baixos — sidecar leve
      cpu    = 32
      memory = 256

      logConfiguration = {
        logDriver = "awslogs"
        options = {
          "awslogs-group"         = "/ecs/booking-agent-xray"
          "awslogs-region"        = var.aws_region
          "awslogs-stream-prefix" = "xray"
        }
      }
    }
  ])
}

resource "aws_ecs_task_definition" "recovery_worker" {
  family                   = "recovery-worker"
  requires_compatibilities = ["FARGATE"]
  network_mode             = "awsvpc"
  cpu                      = "256"   # leve — só Redis I/O e invocações de grafo
  memory                   = "512"
  task_role_arn            = aws_iam_role.recovery_task_role.arn
  execution_role_arn       = aws_iam_role.ecs_execution_role.arn

  container_definitions = jsonencode([
    {
      name      = "recovery-worker"
      image     = "${aws_ecr_repository.app.repository_url}:${var.image_tag}"
      command   = ["python", "recovery_worker.py"]  # mesma imagem, entrypoint diferente
      essential = true

      environment = [
        { name = "REDIS_URL",               value = "redis://${aws_elasticache_cluster.main.cache_nodes[0].address}:6379" },
        { name = "RECOVERY_MAX_ATTEMPTS",   value = "3" },
        { name = "RECOVERY_QUEUE_MAX_SIZE", value = "100" },
        { name = "SERVICE_NAME",            value = "recovery-worker" },
        { name = "OTLP_ENDPOINT",           value = "http://localhost:4317" },
      ]

      # Recovery Worker não expõe porta — não é um servidor HTTP
      # Sem health check de porta; ECS usa o exit code do processo

      logConfiguration = {
        logDriver = "awslogs"
        options = {
          "awslogs-group"         = "/ecs/recovery-worker"
          "awslogs-region"        = var.aws_region
          "awslogs-stream-prefix" = "ecs"
        }
      }
    },
    {
      name      = "xray-daemon"
      image     = "amazon/aws-xray-daemon:latest"
      essential = false
      portMappings = [
        { containerPort = 4317, protocol = "tcp" },
        { containerPort = 2000, protocol = "udp" },
      ]
      cpu = 32; memory = 128
    }
  ])
}

Auth Service Task Definition

hclterraform/task_auth.tf
resource "aws_ecs_task_definition" "auth_service" {
  family = "auth-service"
  cpu    = "256"
  memory = "512"

  container_definitions = jsonencode([{
    name    = "auth-service"
    image   = "${aws_ecr_repository.auth.repository_url}:${var.image_tag}"
    command = ["python", "auth_service/main.py"]

    portMappings = [{ containerPort = 8001, protocol = "tcp" }]

    # Chave privada RSA carregada do Secrets Manager — nunca em variável de ambiente
    # O Auth Service lê via boto3 no startup
    secrets = [
      { name = "RSA_PRIVATE_KEY_ARN", valueFrom = aws_secretsmanager_secret.rsa_private_key.arn },
    ]

    environment = [
      { name = "TOKEN_TTL",    value = "900" },
      { name = "SERVICE_NAME", value = "auth-service" },
    ]

    healthCheck = {
      command  = ["CMD-SHELL", "curl -f http://localhost:8001/.well-known/jwks.json || exit 1"]
      interval = 10; timeout = 3; retries = 3
    }
  }])
}

Por que sidecar e não daemon set

Sidecar por task vs daemon em cada EC2 host

Com ECS Fargate não há EC2 hosts para rodar um daemon set. O sidecar por task é o padrão correto: cada task tem seu próprio X-Ray Daemon acessível via localhost:4317. Containers no mesmo task compartilham o network namespace — sem configuração de rede adicional, sem security group entre eles. O essential=false garante que uma falha do sidecar não derruba o container principal.

ElastiCache — configuração

hclterraform/elasticache.tf
resource "aws_elasticache_replication_group" "main" {
  replication_group_id = "agent-redis"
  description          = "Redis compartilhado: checkpoints, lifecycle, locks"

  node_type            = "cache.r7g.large"  # memory-optimized — checkpoints podem ser grandes
  num_cache_clusters   = 2                   # primary + 1 replica para HA
  automatic_failover_enabled = true

  engine         = "redis"
  engine_version = "7.1"

  # at_rest_encryption: checkpoints podem conter dados sensíveis do usuário
  at_rest_encryption_enabled  = true
  transit_encryption_enabled  = true

  # subnet_group: subnets privadas — Redis nunca exposto publicamente
  subnet_group_name  = aws_elasticache_subnet_group.main.name
  security_group_ids = [aws_security_group.redis.id]

  # Snapshot para recovery de dados em caso de falha grave
  # Checkpoints LangGraph são o dado mais crítico do sistema
  snapshot_retention_limit = 7
  snapshot_window          = "03:00-04:00"

  log_delivery_configuration {
    destination      = aws_cloudwatch_log_group.redis.name
    destination_type = "cloudwatch-logs"
    log_format       = "json"
    log_type         = "slow-log"  # loga queries lentas — útil para diagnosticar Lua scripts
  }
}

Service Discovery — resolução de endereços A2A

Agentes precisam se encontrar sem hardcode de IPs. O AWS Cloud Map (ECS Service Discovery) registra automaticamente cada task com um DNS entry privado.

hclterraform/service_discovery.tf
resource "aws_service_discovery_private_dns_namespace" "agents" {
  name = "agents.internal"
  vpc  = var.vpc_id
}

# search-agent resolve como: search-agent.agents.internal:8000
resource "aws_service_discovery_service" "search_agent" {
  name = "search-agent"
  dns_config {
    namespace_id   = aws_service_discovery_private_dns_namespace.agents.id
    routing_policy = "MULTIVALUE"  # retorna múltiplos IPs — client-side load balancing
    dns_records { ttl = 10; type = "A" }
  }
  health_check_custom_config { failure_threshold = 1 }
}

# auth-service resolve como: auth-service.agents.internal:8001
resource "aws_service_discovery_service" "auth_service" {
  name = "auth-service"
  dns_config {
    namespace_id   = aws_service_discovery_private_dns_namespace.agents.id
    routing_policy = "MULTIVALUE"
    dns_records { ttl = 10; type = "A" }
  }
}
TTL curto para failover rápido

TTL de 10s garante que quando uma task é substituída (deploy, crash), o DNS converge para os novos IPs rapidamente. TTLs longos (60s+) causam janelas de erro durante deploys onde clientes ainda tentam conectar em IPs de tasks antigas já drenadas.

hclterraform/iam.tf
# Task Role do Agent — permissões mínimas para operar
resource "aws_iam_role" "agent_task_role" {
  name = "booking-agent-task-role"
  assume_role_policy = jsonencode({
    Version = "2012-10-17"
    Statement = [{
      Effect    = "Allow"
      Principal = { Service = "ecs-tasks.amazonaws.com" }
      Action    = "sts:AssumeRole"
    }]
  })
}

resource "aws_iam_role_policy" "agent_task_policy" {
  role = aws_iam_role.agent_task_role.id
  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [
      # X-Ray: envia traces
      {
        Effect   = "Allow"
        Action   = ["xray:PutTraceSegments", "xray:PutTelemetryRecords"]
        Resource = "*"
      },
      # Secrets Manager: lê CLIENT_SECRET e AUTH_SERVICE_URL
      {
        Effect   = "Allow"
        Action   = ["secretsmanager:GetSecretValue"]
        Resource = [
          aws_secretsmanager_secret.client_secret.arn,
          aws_secretsmanager_secret.auth_url.arn,
        ]
      },
      # CloudWatch Logs: escreve logs do container
      {
        Effect   = "Allow"
        Action   = ["logs:CreateLogStream", "logs:PutLogEvents"]
        Resource = "arn:aws:logs:*:*:log-group:/ecs/booking-agent:*"
      }
      # Nota: Redis é acessado via TCP/TLS — sem permissão IAM necessária
    ]
  })
}

# Task Role do Recovery Worker — subconjunto das permissões do agent
resource "aws_iam_role_policy" "recovery_task_policy" {
  role = aws_iam_role.recovery_task_role.id
  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [
      {
        Effect   = "Allow"
        Action   = ["xray:PutTraceSegments", "xray:PutTelemetryRecords"]
        Resource = "*"
      },
      {
        Effect   = "Allow"
        Action   = ["logs:CreateLogStream", "logs:PutLogEvents"]
        Resource = "arn:aws:logs:*:*:log-group:/ecs/recovery-worker:*"
      }
      # Recovery Worker não acessa Secrets Manager — não faz chamadas A2A autenticadas
    ]
  })
}

# 1. Recovery Worker parou de rodar
# desired_count=1 mas running_count=0 → worker morreu e não foi substituído
resource "aws_cloudwatch_metric_alarm" "recovery_worker_down" {

  comparison_operator = "LessThanThreshold"
  evaluation_periods  = 2
  metric_name         = "RunningTaskCount"
  namespace           = "ECS/ContainerInsights"
  period              = 60
  statistic           = "Average"
  threshold           = 1
